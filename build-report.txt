What changed in revision 2
---------------------------
When --reset-subsystems is used, Sensor is now tested before Frozen by default
(--sensor-first, tied to --reset-subsystems unless explicitly overridden), and immediately after
the reset-expander sequence releases, Sensor's bootloader baud (38400) is probed with repeated
Ping attempts (default: every 100ms for up to 3000ms, or until a valid response) instead of a
single Ping several seconds later behind a Frozen-first ordering. Frozen's optional GetFirmware
step is now skipped by default (--skip-frozen-firmware, default on) since it was previously
delaying the whole Frozen phase behind a timeout for no diagnostic benefit; its outcome was
already structurally incapable of invalidating a successful Frozen Ping, and still is. New CLI
options: --sensor-first, --sensor-bootloader-probe-ms, --sensor-bootloader-interval-ms,
--skip-frozen-firmware. New summary/JSON fields covering the bootloader retry-probe's attempt
count, bytes received, valid-frame/decode-error counts, and first-byte/first-valid-frame latency
relative to reset release. No new command is reachable: the whitelist (Ping, GetHardwareInfo,
GetFirmware(Hash), JumpToFirmware per subsystem) and the two-layer enforcement
(closed probe enums + SafetyAudit) are unchanged; see SAFETY.md.

Runtime smoke test
-------------------
The exported dist/opensleep-diagnostic-aarch64-static was additionally executed directly on the
x86_64 build host (via the same transparent QEMU binfmt path described above) as a sanity check
independent of the build container:
  - `--help` lists the four new options (--sensor-first, --sensor-bootloader-probe-ms,
    --sensor-bootloader-interval-ms, --skip-frozen-firmware) alongside the unchanged prior set;
    still no temperature, pump, priming, vibration, alarm, raw-command, or profile option exists.
  - `--sensor-first --sensor-bootloader-probe-ms 100 --sensor-bootloader-interval-ms 30
    --timeout-seconds 1` (no --reset-subsystems) runs the sensor-first path on demand, correctly
    reports "Sensor tested first after reset: YES" and the new bootloader-probe summary fields
    (all zero/unavailable here since this host's /dev/ttyS2 isn't a real Sensor MCU), and exits
    20 (I2C open failure on this non-Pod host takes precedence, as designed).
  - `--reset-subsystems --sensor-first=false` correctly reports "Sensor tested first after
    reset: NO", confirming the explicit-override path works, not just the tied-to-reset default.
  - `--skip-frozen-firmware=false` correctly flips the logged "Frozen GetFirmware requested"
    line to true, confirming the backward-compatibility override works.
  - `Arch:` in the startup log correctly reports `aarch64` (read from the running binary's own
    target, not the host), confirming this is genuinely the cross-compiled artifact.
